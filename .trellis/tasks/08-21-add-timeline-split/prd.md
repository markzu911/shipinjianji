# 新增时间轴分割功能

## Goal

在文字剪辑时间轴右上角新增剪映式分割按钮，让用户按当前播放头把所在的剪后视频片段无损分为前后两个相邻片段，并能以这些边界为单位安全地选择、删除和恢复片段。

## Background

- 参考图 1 展示剪映在播放头处执行“分割”的交互；参考图 2 对应本项目 `#cutFrameTimeline`，按钮应位于该时间轴区域右上角，而不是视频播放器或页面全局工具栏。
- 当前时间轴已有唯一播放头 `#cutFrameTimelinePlayhead`，`getCutPlaybackFrameState()` 同时提供剪后时间和源时间，可作为分割位置的坐标转换入口。
- 当前 cut draft 只持久化 `textRanges`、`noSpeechRanges` 和 `timelineRanges`，尚无基础视频 clip 或 split-point 模型。预览、公共时间轴和 compose 均由同一个 Store frame 与删除时间映射派生。
- 当前“调整文字分段”弹窗已有 `splitSegmentButton`，它通过 `/editable-segments` 按所选文字拆分转写段落；本任务是播放头处的视频时间轴分割，不能复用该按钮的文字语义或混用接口。

## Requirements

- R1：在文字剪辑时间轴标题区域右上角显示带剪刀图标的“分割”按钮，位置与第二张参考图的时间轴容器一致；桌面和 375px 宽度不得遮挡时间、轨道或状态提示。
- R2：点击按钮时，以当前剪后播放头为准，将播放头所在的保留视频片段分为前后两个首尾相接的片段；分割本身不得删除媒体、插入间隙、改变总时长、移动播放头或产生声音断层。
- R3：分割位置必须通过现有剪后时间到源时间映射保存为稳定的源时间锚点，不能把剪后时间直接当源时间持久化。已有删除范围变化后，分割点仍保留原锚点；落入删除区间时隐藏，恢复后重新出现。
- R4：位于整个时间轴起点/终点、当前片段边界、已删除区间或不存在可分割媒体时，按钮不可执行重复或零长度分割，并提供可理解的禁用状态或状态反馈。
- R5：分割结果在当前时间轴中显示清晰边界，刷新后可恢复，并进入现有撤销/重做与 cut-draft revision 语义；一次分割只产生一个领域事务。
- R6：预览、公共时间轴、艺术字、画中画和统一生成继续消费同一个 Store/media/timeline owner；分割不得重载基础视频、创建第二套时间轴或改变普通文字/空白/手动范围的既有声学边界行为。
- R7：本任务新增的“分割”命名、DOM id、Store command 和持久字段必须与现有文字段落 `splitSegmentButton` / `/editable-segments` 明确区分。
- R8：本期分割后的片段支持独立选择、删除、恢复和撤销/重做；删除前沿用现有确认交互，已删除片段在剪后时间轴的拼接点保留可访问的恢复入口。
- R9：分割点是独立结构状态，使用源时间锚点持久化；片段删除继续写入统一 `timelineRanges` 并由现有 preview/compose 消费，不建立只影响界面的私有删除集合。
- R10：删除完整分割片段时，其前后端点必须严格使用该片段的源时间锚点，并标记为分割精确边界。服务端不得对这类端点执行声学吸附；普通手动 `timelineRanges` 仍保持现有语音安全吸附。
- R11：分割本身只增加项目结构 revision，不增加 `timingRevision`；删除/恢复片段会改变剪后时间，继续增加 `timingRevision`。服务端仅确认新的 cut-draft revision 时不得额外生成用户编辑事务。

## Acceptance Criteria

- [ ] AC1：桌面与 375px 下，分割按钮稳定显示在文字剪辑时间轴右上角，点击目标至少 44px，图标、文字、时间和轨道不重叠。
- [ ] AC2：播放头位于有效片段内部时点击一次，时间轴出现两个无缝相邻片段；预览当前位置、剪后总时长、声音和画面内容均不改变。
- [ ] AC3：分割点使用源时间锚点持久化；刷新、草稿保存和服务端 revision 更新后仍落在同一媒体位置，不因已有删除区间导致漂移。
- [ ] AC4：起点、终点、已有分割点、删除区间和空时间轴不会产生零长度或重复片段，按钮状态和反馈符合对应条件。
- [ ] AC5：分割、撤销、重做分别只产生一个有序历史事务和一次有效 Store revision；分割不改变 `timingRevision`，连续分割可逐次撤销并恢复。
- [ ] AC6：分割前后 document、基础 video、公共预览、ArtTool、PipTool 与时间轴 owner identity 不变，基础 video 不写 `src`、不调用 `load()`，iframe 数量保持 0。
- [ ] AC7：现有文字段落拆分、文字/空白/手动时间轴删除、声学边界、刷新恢复、公共预览和 compose 回归不受影响。
- [ ] AC8：任一分割片段可独立选中并经确认后删除；删除后相邻保留片段无损拼接，拼接点可恢复该片段，撤销/重做按事务逐步还原片段及命令前后的选择状态。
- [ ] AC9：删除分割片段提交的物理 `start/end` 与对应源时间锚点一致，服务端声学解析不会移动任一端点；相邻片段开头声音不会被多删，目标片段尾音不会因保护机制残留。
- [ ] AC10：不出现片段拖动换序、变速或转场入口；分割片段的删除结果进入统一 cut draft、预览和 compose，生成前会等待最新 draft revision 落稳。

## Out of Scope

- 不把现有文字段落拆分改造成视频分割。
- 不加入片段拖动换序、变速、转场或多轨磁吸能力。
- 不改变普通文字删除、空白删除和自由拖选时间轴范围的声学吸附策略。
- 不改变媒体编码参数或建立新的基础视频、预览、时间轴、生成 owner。
