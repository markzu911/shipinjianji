# 放大文案列表字体并下移播放跟随锚点

## Goal

将文字剪辑列表中的文字层级统一放大 `20%`，并把播放跟随时绿色活动文案的常规停靠位置向下移动三个实际文案行高度，使当前播放位置更接近面板上部偏中区域，同时保持列表顺序、播放语义和滚动动画稳定。

## Background

- 用户截图显示绿色正在播放行当前停靠在吸顶工具栏下方的第一行位置，希望向下移动三个位置。
- 现有文字列表采用紧凑字号：正文 `10px`、时间 `9px`、播放 badge `7px`、空白标题 `9px`、空白 meta `8px`。
- 播放跟随由 `web/transcript-follow-scroll.js` 唯一拥有，当前锚点为工具栏底部加 `8px`；截图仅作为视觉证据，不作为产品指令。

## Requirements

- R1：文案列表正文、时间、播放状态 badge、空白/删除标题和辅助 meta 字号分别在现值基础上放大 `20%`；图标、勾选圆、播放按钮和其他页面文字不随本任务缩放。
- R2：对应目标字号为正文 `12px`、时间 `10.8px`、播放 badge `8.4px`、空白标题 `10.8px`、空白 meta `9.6px`。
- R3：文字放大后行高按内容自然增长，不裁切、不重叠、不产生列表或页面横向溢出；桌面和 `375px` 窄屏都保持可用。
- R4：播放跟随的常规目标锚点在原“工具栏底部 + 8px”基础上增加 `3 × 当前活动行实际高度`，即绿色活动行向下三个位置；不得用固定像素假设所有行等高。
- R5：目标锚点不得把活动行推出滚动面板底部。首部、尾部、长换行行、连续切段和 reduced-motion 继续使用既有 clamp、尾部余量和单调动画契约。
- R6：只改变视觉字号和播放跟随位置，不改变文案 DOM 顺序、播放/暂停、source time、删除状态、按钮数量、滚动中断或草稿保存行为。
- R7：同步更新静态资源版本，刷新后必须加载新 CSS 和跟随脚本。

## Acceptance Criteria

- [x] AC1：浏览器计算样式分别得到正文 `12px`、时间 `10.8px`、播放 badge `8.4px`、空白标题 `10.8px`、空白 meta `9.6px`。
- [x] AC2：活动行可正常停靠时，其最终 top 等于原基础锚点加三个该行高度；跟随控制器仍只移动唯一真实行并保留无交互占位。
- [x] AC3：目标位置接近面板底部时活动行完整可见；连续尾部行不先上弹再下移，reduced-motion 直接得到同一最终位置。
- [x] AC4：普通、已删除和空白行在桌面与 `375px` 下无文字裁切、重叠或横向页面溢出，按钮和图标几何保持不变。
- [x] AC5：播放按钮、删除/恢复、用户滚动中断、重渲染恢复顺序、单次 scrollTop 写入和现有跟随动画回归保持通过。
- [x] AC6：前端契约、真实 Chromium 工作流、JS 语法和 `git diff --check` 通过。

## Out Of Scope

- 修改时间轴文案块、视频字幕/艺术字字号、全应用字号或颜色方案。
- 改变文案列表排序、播放时间、删除范围、VAD/ASR、预览或导出。
- 重写现有真实行 reparent、FLIP 或尾部动画架构。

## Key Decision

“向下三个位置”按活动行自身的实时高度计算，而不是固定 `32px × 3`；这样长文案换行和放大后的动态行高仍保持语义一致。
