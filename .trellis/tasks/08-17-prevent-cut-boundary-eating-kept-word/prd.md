# 防止自动裁剪误删保留文案

## Goal

建立一条通用安全契约：AI 文字删除的音频边界可以向相邻空白吸附，自动空白范围可以裁掉无文案的时间，但两者都不得删除未被选中的文案或语音。

## Background

- 真实草稿 `data/jobs/ea33fda8-9fb9-4524-ab14-21c287d1c187/cut-draft.json` 中，AI 语义选择仅为“周围人的天花板就成了自己的极限。”（`103.080–105.800s`），但已保存的物理范围被吸附为 `101.795–107.785s`，因而覆盖后续“为啥”。
- `server/app.py:2763-2769` 为文字草稿建立边界时同时传入头部和尾部 guard，使物理范围可进入前后保留文字的时间。
- 前后端都已有“从空白范围中扣除识别语音”的保护函数，但之后仍会用 `0.12s` 间隔容差合并区间，存在跨过较短保留语音的通用风险。
- `web/app.js:487-535` 的文案状态同时参考语义文字范围与合并后物理范围，使空白扩展误入文字时也会显示删除线。
- `.trellis/spec/backend/media-and-timeline.md:39` 已规定“删除边界不会吞掉保留语音”；`.trellis/spec/frontend/architecture-and-state.md:65-73` 已区分文字删除与空白删除的状态所有者。

## Requirements

- R1：AI 文字删除的物理开始和结束边界都必须严格受相邻保留文字单元限制，不得用头部或尾部 guard 进入保留语音。
- R2：`originalStart/originalEnd` 继续是文字删除语义的唯一所有者；`start/end` 只表示安全吸附后的物理裁剪边界。
- R3：自动空白 `noSpeechRanges` 在前端预览与后端生成前均必须扣除所有识别文字时间；完全落在文字上的空白候选不得产生任何物理删除。
- R4：自动区间合并不得因 `0.12s` 容差重新跨过已保护的短文字单元；合并后的最终自动删除集仍必须与保留文字无交集。
- R5：文案列表中的删除状态只由文字语义选择或用户明确提交的手动时间轴删除决定；空白范围和文字的前后静音扩展不得将文案渲染为已删除。
- R6：删除词与保留词之间有真实空白时，边界仍可吸附到该空白中的低谷，但不得越过保留文字边界。
- R7：前端预览、草稿 PUT 响应、公共预览、单独剪辑生成和统一组合生成必须消费同一安全契约，不得仅在界面隐藏误删。
- R8：修正后重算 `adjacentSilenceBefore/After`，保持草稿重复 PUT 幂等。
- R9：仅修正后续保存和生成链路，不扫描、迁移或手工改写已有 `data/jobs` 草稿。
- R10：新转写必须在兼容字段 `segments[].asrWords` 中原样保留 ASR 返回的 word 时间边界；现有 `segments[].words` 继续用于 Jieba 自然分词、文案展示和 AI 语义分析，不能再被误当成模型原始边界。
- R11：文案仍按字符显示、播放和修正；文字删除与保留保护必须使用 `segments[].words` 派生的字符时序。原始 `asrWords` 可能跨越自然词边界，只能作为声学/模型参考，不能作为不可分割删除单元。
- R12：后端必须把恶意或旧客户端提交的局部文字范围规范到与其相交的安全字符单元；某段缺少 `words` 时，逐段从 `asrWords` 或 segment 文本/时长派生字符级回退。手动时间轴删除继续保持精确范围。
- R13：草稿预览、公共预览、单独剪辑、统一组合和 retained transcript 必须消费同一组字符级文字语义范围；音频低谷吸附不得越过上一保留字符结束或下一保留字符开始。
- R14：手动 `timelineRanges` 与文字 `textRanges` 的字符删除语义必须保留来源。手动范围仅在经过完整句段复验的 forced 字符区间与其精确 `originalStart/originalEnd` 相交时删除该字符；forced 缺失或无效时保守保留不确定文字，同时保持媒体物理删除范围不变。
- R15：用户在剪后连续时间轴拖出的一个选区如果跨过既有删除洞，确认时必须按当前 retained spans 拆成多个不连续源时间 `timelineRanges`；不得只保存首尾两个源时间并重新引入洞内内容。
- R16：手动范围只有在覆盖 forced 字符超过一半时才删除该字符；小于等于半字的边缘重叠必须保留字符。粗时间判定出的连续删除 run 也必须至少包含一个超过半字的 forced/acoustic 覆盖，才能用于声学边界吸附。
- R17：时间轴删除对应的文案身份由同 revision 的服务端 retained projection 决定；投影缺失、过期或 owner 无效时前端保守保留文字，不能再用粗 ASR 中点猜测整字删除。

## Acceptance Criteria

- [x] AC1（R1、R2）：删除一段文字时，物理范围在前后两侧都不与未选中文字单元重叠，语义范围保持不变。
- [x] AC2（R3、R4）：空白候选部分或完全覆盖文字时，仅保留无文字碎片；即使中间保留文字短于 `0.12s`，合并后也不得将其删除。
- [x] AC3（R5）：删除空白区域时，相邻文案不出现删除线或恢复按钮；只有文字语义选择和明确的手动时间轴删除会改变文案删除状态。
- [x] AC4（R6）：文字之间有安全空白时，音频边界仍可延长至空白内低谷，但不越过下一保留文字，也不早于上一保留文字结束。
- [x] AC5（R7、R8）：草稿响应与最终生成的范围一致，`adjacentSilenceBefore/After` 正确，相同草稿重复 PUT 不漂移。
- [x] AC6（R7）：前端安全投影、后端裁剪范围、保留 transcript 和组合生成回归全部通过，不存在“文字看似保留但成片已删除”的差异。
- [x] AC7（R9）：实现不扫描、迁移或改写现有 `data/jobs` 草稿；旧草稿在下次正常 PUT 保存后应用新契约。
- [x] AC8（R10）：模型返回多字 word 时，转写结果的 `asrWords` 保留该 word 的原始起止时间，`words` 仍可按 Jieba 重分词；标点校对不得改变 `asrWords` 的时间边界。
- [x] AC9（R11、R12）：`words=一起/给/一起/给`、`asrWords=一起/给一/起给` 时，删除第一个“一起给”最多结束于下一个“一”开始；`words=觉得/你`、`asrWords=得你` 时，删除“觉得”不得删除“你”。恶意局部文字范围会规范到相交字符，手动时间轴范围不扩大。
- [x] AC10（R13）：建议吸附、草稿 PUT、前端预览、剪辑/组合生成、恢复/撤销投影和 retained transcript 使用同一字符级结果；仅有 `asrWords` 或 segment timing 的历史分段仍按逐字符回退加载和编辑。
- [x] AC11（R14）：手动选区 `32.053–39.829s` 与下一字粗时间 `37.120–37.480s` 重叠、但该字 forced 起音为 `39.850s` 时，草稿投影与最终生成均保留下一字，物理删除范围仍严格等于用户选区；forced 缺失时同样不误删文字。
- [x] AC12（R15）：既有源时间删除洞 `32.730–39.680s` 后，在剪后时间连续拖选对应源区间 `32.096–39.872s`，草稿只新增 `32.096–32.730s` 与 `39.680–39.872s`，不产生扁平的 `32.096–39.872s`。
- [x] AC13（R16、R17）：右侧新范围与 `39.850–40.030s` forced 字符仅重叠 `22ms` 或 `60ms` 时字符保留；明确覆盖 `39.860–40.000s` 超过半字时字符删除。服务端投影缺失或归属无效时，浏览器不把相邻文字显示为已删除。

## Out Of Scope

- 不改变 AI 文案删除建议的类型或置信度；建议和用户文字删除沿用自然词/字符语义，不以原始 ASR token 为最小单位。
- 不禁止用户通过手动时间轴选区明确删除包含文字的内容；该路径继续使用现有二次确认。
- 不重写波形低谷检测算法，不改变播放、艺术字或画中画功能。
- 不扫描、迁移或手工改写用户 `data/jobs` 中的既有草稿。

## Key Decisions

- “保留文字不可穿越”是自动裁剪的最终不变量，优先级高于尾音延长和小间隔合并。
- 模型原始 ASR word 仅保存声学/模型边界；媒体删除与保留保护以自然分词后派生的字符时序为最小安全单元，避免原始 token 跨自然词边界时吞掉下一字。
- 文字语义删除、文字物理静音扩展、自动空白删除和手动时间轴删除是四种不同语义，合并时不得丢失来源。
- 剪后时间选区的语义是 retained timeline 上的区间集合；跨删除洞时必须保留为多个源区间，不能用单一源区间近似。
- 手动时间轴对字符身份的判定采用复验 forced 区间和最小有效覆盖阈值；媒体物理范围仍保持用户确认的精确区间。
- 对外兼容字段 `transcriptRanges` 继续保持原有扁平形状；新草稿生成记录额外保存文字与手动时间轴的来源范围，历史记录缺少来源时沿用旧兼容读取。
- 只有经过 `cutDraftRevision` 校验的生成请求可保存草稿来源范围；旧请求的范围即使与草稿数值相同，也不得据此推断来源。
- 普通时间轴删除只有在 coarse 删除 run 获得超过半字的 forced/acoustic 覆盖确认后才允许向声学端点吸附；仅由 VAD 授权的物理端点还必须位于用户端点 `0.20s` 内，forced/PCM 已证明的尾音边界可继续超距。
- 后端对最终媒体范围负责，前端使用同一契约保证预览和显示一致；不以仅隐藏删除线代替实际媒体保护。
- 用户已明确不处理现有任务草稿，本次只修复后续正常保存与生成。

## Risks And Deferred Items

- 字符时序仍由词级时间均分推导，不代表独立声学对齐；边界冲突时优先保留下一个字符，接受少删尾音而不接受误删文案。
- 旧草稿在下次编辑并保存之前不会自动改变。
