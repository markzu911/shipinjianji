# 时间轴选区二次确认交互

## Goal

降低文字剪辑时间轴手动框选的误删除风险，让用户先完成区间选择和边界微调，再通过明确的二次点击发起删除确认。

## Background

- 当前文字剪辑时间轴已经支持创建删除区间、显示左右边界手柄，以及拖动区间主体或两侧手柄调整范围。
- 当前实现会在首次拖选结束的 `pointerup` 里立即调用删除确认弹窗；弹窗取消后会直接移除刚创建的区间。证据：`web/app.js` 中的 `beginCutTimelineSelection`、`requestTimelineRangeConfirmation` 和 `cancelPendingTimelineRange`。
- 当前页面辅助文案写着“松开后弹窗确认”，对应静态断言位于 `tests/test_app.py`，本次需要同步更新。
- 本任务是父任务 `08-13-project-optimization-audit` 下首个可独立验收的交互优化，不扩展到艺术字或画中画时间轴。

## Requirements

- R1：用户在文字剪辑时间轴首次拖动框选出有效区间并松开后，不立即显示删除确认弹窗。
- R2：首次框选完成后保留待确认选区，显示选中态和左右边界手柄，允许用户拖动两侧手柄微调开始、结束时间。
- R3：拖动选区主体或任一边界手柄时，以及拖动结束时，均不得触发删除确认弹窗。
- R4：只有用户在选区已创建且本次指针操作未形成拖动时，再次点击选区主体，才显示现有的删除确认弹窗。
- R5：用户在删除确认弹窗中选择“取消”后，保留当前待确认选区及其微调结果，不提交删除；用户可继续调整或再次点击选区主体重新确认。
- R6：键盘用户聚焦待确认选区后按 Enter，仍可打开同一个删除确认弹窗；Delete/Backspace 的既有取消待确认选区或恢复已删除区间行为保持可用。
- R7：待确认选区未确认前继续阻止生成剪辑视频，沿用当前状态约束。
- R8：同步更新页面辅助文案、状态提示、无障碍标签和自动化测试，使其描述“先微调、再次点击确认”的真实行为。
- R9：保留现有的文字边界吸附、最短区间校验、预览、撤销记录和删除确认弹窗样式。
- R10：待确认选区提供可见的 `×` 按钮；点击后立即取消该选区，不触发删除确认，且按钮具备清晰的无障碍名称和焦点态。
- R11：待确认选区采用克制的工具型视觉：弱化粗白描边，关闭图标融合在选区内部右上角，不显示独立方块、外置片段或高饱和底色；保留清晰边界、可辨识手柄、时间标签和键盘焦点反馈。

## Acceptance Criteria

- [x] AC1（R1、R2）：首次拖选有效范围并松开后，页面保留带左右手柄的待确认选区，删除确认弹窗未出现。
- [x] AC2（R2、R3）：用户可反复拖动左右手柄或区间主体，范围与时间提示同步更新，任一拖动过程和结束时均不弹窗。
- [x] AC3（R4）：用户在未拖动的情况下再次点击待确认选区主体，删除确认弹窗只打开一次，并显示微调后的最终时间范围。
- [x] AC4（R5）：删除弹窗选择“取消”后弹窗关闭，选区及微调后的边界保持不变，删除未提交且仍可继续调整或再次确认。
- [x] AC5（R6）：聚焦待确认选区并按 Enter 可以打开删除确认弹窗；键盘边界调整不会误触发弹窗，Delete/Backspace 保持既有语义。
- [x] AC6（R7）：存在待确认选区时，“生成剪辑”不可用；确认删除后区间进入已提交状态并恢复既有生成条件。
- [x] AC7（R8）：界面不再出现“松开后弹窗确认”等过时说明，相关静态与交互测试通过。
- [x] AC8（R9）：文字选择删除、AI 建议删除、空白剪辑、艺术字时间轴和画中画时间轴的既有交互不受影响。
- [x] AC9（R10）：待确认选区显示 `×` 按钮；鼠标或键盘激活后选区消失、确认弹窗不出现、生成条件恢复，并显示取消反馈。
- [x] AC10（R11）：选区、手柄、时间标签和内部关闭图标在桌面及 375px 窄屏下层级清晰、无外置方块、重叠或裁切，并可通过鼠标和键盘取消选区。

## Out of Scope

- 不重新设计删除确认弹窗的视觉样式或文案结构。
- 不新增精确时间输入框、帧吸附或新的快捷键。
- 不修改文字选择、AI 建议和空白剪辑的删除确认流程。
- 不修改艺术字、画中画及顶层统一时间轴的片段交互。
- 不改变后端删除区间接口、媒体裁剪算法或持久化格式。

## Key Decisions

- 删除确认弹窗取消后保留待确认选区，不把“取消弹窗”解释为“取消选区”。
- 以无拖动的选区主体点击作为鼠标确认入口；手柄交互只负责调整边界。
- 本任务按轻量前端交互改动处理，使用单一 `prd.md`，不增加新的状态模型文件或后端契约。
