# ASR 与 VAD 联合分段静音边界

## Goal

对 AI 与用户形成的每个文字分段/删除边界，使用 ASR/强制对齐确认相邻字符身份，再用局部 VAD 与 PCM 找到两字之间的真实无声走廊并确定媒体切点，使被删除文字的尾音或首音一点都不残留。若连续发音导致无法同时保全两侧，则优先彻底清除被删除人声，允许相邻保留字轻微受损。

## Background

- 用户样本的目标衔接是：保留“所有人” -> 删除前一次“一起给” -> 保留后一次“一起给你”。当前删除起点仍会带出被删“一”的一点声音。
- 同一素材与模型曾把下一处保留“一”的起点分别对齐到 `29.790s` 和 `29.810s`，存在约 `20ms` 强制对齐漂移，单独使用字符时间不能保证无残音。
- 完整 `27s-32s` 连续语音在 FSMN-VAD 中返回一个 speech 区间；VAD 必须在相邻字符限定的局部走廊内使用，不能把全局 VAD 分段直接当字符边界。
- 当前用户文案拆分入口是“调整文字分段”弹窗：选中文字后点击“拆分”。后端 `apply_transcript_segment_operation()` 按字符 token 切组，`build_editable_segment_from_tokens()` 直接使用首尾 token 的旧时间，未经过 VAD/PCM 声学校准。
- 浏览器预览通过跳过删除区间模拟剪辑。当前共享播放帧回调只更新视觉状态，删除区间跳转依赖 `timeupdate`，必须与最终 FFmpeg 输出分别验证。

## Requirements

- R1. 建立唯一的相邻字符声学边界解析器，统一服务 AI 语误删除、用户文字删除、普通手动时间轴删除、系统自动文字分段，以及用户在“调整文字分段”中创建的文字段落。
- R2. 每个边界以左侧最后一个可发声字符和右侧第一个可发声字符为语义锚点；使用完整句段 ASR/`fa-zh` 证据限定局部走廊，再在该走廊内融合 FSMN-VAD non-speech 与 PCM 持续低能量证据。
- R3. 存在可信无声走廊时，最终采样点必须位于走廊内。删除起点必须早于被删首字完整起音，删除终点必须晚于被删尾字完整尾音，同时不得进入相邻保留字的声学主体。
- R4. 不存在可信无声走廊时，同一字符转换保存三个结果：中性展示边界、删除左侧时使用的激进边界、删除右侧时使用的激进边界。用户实际删除哪一侧，就选择对应方向性边界；优先保证被删声音绝不残留，允许轻微削弱保留字。
- R5. 用户文案拆分后，新段落的起止时间与时间轴文案块立即显示中性声学边界；选择删除某一侧后，两处展示同步更新为对应方向性物理边界。语义字符范围和原始 ASR 时间必须单独保留。
- R6. VAD 只决定声学边界，不判断口误、不取消 AI 删除、不改变用户选中的字符身份。`originalStart/originalEnd` 与字符身份始终表示语义意图，物理字段只负责媒体裁剪。
- R7. 同一个相邻字符转换无论从 AI 范围、用户文字范围、普通 timeline 范围还是文案拆分段落命中，都必须使用同一边界 key 和同一解析结果。草稿 PUT 持久化最终物理范围，公共预览、单独剪辑、统一组合与 FFmpeg 生成只消费该范围，生成阶段不得重新解析。
- R8. FSMN-VAD 模型不可用、下载/校验/推理失败或返回无效时，安全降级到现有 `fa-zh + PCM` 路径并记录原因，不阻断转写、文案拆分、草稿保存或生成。VAD 可用但没有静音走廊时走 R4 的方向性激进策略，不得伪装成 VAD 失败。
- R9. 诊断必须记录边界 key、左右字符与句段位置、语义 fallback、forced 候选、VAD speech/non-speech 区间、PCM 低能走廊、中性/左右删除最终点、采用方向、证据来源、模型 revision 与降级/激进原因。
- R10. 浏览器实时预览必须在播放帧时钟中及时跳过删除范围，不能只依赖低频 `timeupdate`。预览和最终 FFmpeg 分别验证，不能通过继续扩大删除范围掩盖预览调度问题。
- R11. 验收以真实生成音频、局部 PCM/频谱和人耳试听为准；二次 ASR 与诊断状态只能作为辅助证据，不足一个音节的首音或尾音残片也判失败。

## Acceptance Criteria

- [ ] AC1. 用户目标素材删除前一次“一起给”后，成片衔接为“所有人一起给你”；听不到被删“一”的任何残音，后一次“一起给你”的正文可理解。
- [ ] AC2. 相邻字符间存在静音走廊时，中性、删除左侧和删除右侧边界收敛到同一走廊；最终点位于 VAD non-speech 与 PCM 持续低能区间的交集中。
- [ ] AC3. 相邻字符连续发音、没有可信静音走廊时，左右删除使用不同方向性边界；输出允许轻微削弱保留字，但局部试听与频谱不得检出被删除人声残片，诊断标记 aggressive fallback。
- [ ] AC4. 用户在“调整文字分段”中选中文字并点击“拆分”后，新段落时间和时间轴文案块立即使用中性物理边界；删除任一侧后同步切换到对应方向性边界，刷新后不漂移。
- [ ] AC5. 同一字符转换被 AI 删除、用户文字删除、普通 timeline 删除和用户文案拆分引用时，返回相同 boundary key 和对应方向的 final；重复保存结果幂等。
- [ ] AC6. `originalStart/originalEnd`、原始 ASR/forced 字符证据和用户选择的字符身份保持不变；物理边界变化不改写文案语义或误删未选字符。
- [ ] AC7. cut draft 保存的物理范围与浏览器预览、`/cuts`、`/compose` 和 FFmpeg 输入完全一致；生成阶段对 forced alignment、VAD 和 PCM 的新增调用数为零。
- [ ] AC8. 浏览器实时预览不会在删除开始处短暂播放被删首音；预览调度问题与媒体边界问题分别有回归测试。
- [ ] AC9. VAD 失败时功能可完成并公开稳定 fallback reason；既有 forced alignment、重复转场、保留字符保护、editable segment 拆分/合并、草稿 revision 和 retained transcript 回归继续通过。
- [ ] AC10. Windows 与 macOS 复用现有 FunASR/Torch 依赖；VAD 模型按固定 revision 校验并在进程内只初始化一次，普通单元与浏览器测试不下载真实模型。

## Out of Scope

- 使用 VAD 判断哪段文字是口误，或替代现有 AI 语义删除建议。
- 只为全局 `noSpeechSuggestions` 增加静音候选；本任务解决相邻字符、文字段落和删除端点的声学边界。
- 时间轴播放头的 `split_exact` 视频片段拆分；它不是用户本次所说的“手动拆分”，继续保持现有精确帧契约。
- 使用固定毫秒 padding、统一扩大所有删除范围、全局淡入淡出或音量遮盖来隐藏错误边界。
- 批量改写已有 job、历史成片或用户附件；历史数据按缺少新字段的兼容路径读取。
