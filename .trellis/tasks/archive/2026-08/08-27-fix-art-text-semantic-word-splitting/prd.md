# 修复艺术字语义词被拆分

## Goal

修复文案修改、用户点击文案拆分及删除后，全文文案艺术字虽然字符完整但 cue 分段违背既有语义拆分规则的问题，使艺术字同时满足字符守恒、原语义边界稳定继承和合法降级边界约束。

## Background

- 用户截图显示字符已经恢复完整，但语义词被拆到相邻艺术字 cue，例如“其实”被拆为“其”与“实”，“该有的”被拆为“该”与“有的”。
- 触发顺序包含：修改一次文案 -> 用户点击文案拆分 -> 删除拆分后的文案。
- 初始全文艺术字由后端按 `segments[].words` 词块、AI 语义断点和本地不完整短语修复规则生成。AI 只能选择词块后的断点，初始生成不会从词块中间硬切。
- 文案保存路径 `update_transcript_track_text_for_segment()` 当前按重叠 cue 的 source 时长比例直接分配字符，不读取原 cue 文本差分或合法语义边界。只调整 cue 时长比例即可稳定复现“其实”变为“其/实”和“该有的”变为“该/有的”。
- 后续 cut reconciliation 的 `partitionTranscriptTrack()` 再按旧 cue source 边界映射到字符中点，缺少 source 投影时按字符容量比例取整；两个分支都允许在任意字符位置切分。独立 Node 最小复现得到 `前文其 / 实该 / 有的后文结束`。
- 上一轮 `251d2ef` 为消除首字缺失引入全轨单调字符分配，正确解决了字符丢失，但没有把原艺术字语义分段作为边界约束，因此暴露出本次系统性回归。
- 截图仅作为问题证据，不作为产品指令。

## Requirements

- R1：当前 `cut.transcript` 的可见字符序列继续作为全文艺术字字符身份的唯一权威；每个未删除字符必须且只能出现一次，顺序与当前文案一致。
- R2：已有全文艺术字 cue 的文本分区代表初始语义拆分结果。文案变化后应通过单调文本差分投影旧 cue 边界，未被编辑的词语或短语不得仅因 source 锚点漂移、cue 时长比例或删除前后总字数变化而跨 cue。
- R3：后端文字保存同步不得再按重叠 cue 时长比例对整段新文案任意数汉字。相同字符块保留原 cue 归属；插入、替换和删除只影响对应差分区，并保持 cue 时间、source anchors、样式和 track identity 稳定。
- R4：前端 cut reconciliation 必须在同一 `trackId` 内整体、单调地投影语义边界。source/edited 时间仅用于 cue 保留判断、时间重映射和同等合法候选的距离偏好，不能直接授权词内字符切点。
- R5：缺少可复用差分锚点时，只能在当前 transcript 的合法词块/段落边界中选择单调切点，并拒绝孤立单字、受保护短语尾或弱起始词等既有艺术字规则明确不接受的边界；没有合法切点时允许合并或 suppress cue，不得硬切语义词。
- R6：修改文案、用户点击文案拆分、删除拆分后的文案、撤销/恢复，以及本地临时投影切换到服务端投影的组合链路，都必须满足 R1-R5。
- R7：修复必须覆盖同类任意文案，不得为“其实”“该有的”等示例维护硬编码特例。
- R8：手动艺术字、文案删除范围、VAD/PCM 边界、基础视频、画中画、艺术字视觉样式和用户选择不得被此次修复改变。
- R9：Store、公共时间轴、统一预览、草稿恢复和 compose 必须消费同一份修复后的艺术字 cue 文本与 timing。

## Acceptance Criteria

- [x] AC1：后端文字保存最小复现中，无论重叠 cue 时长比例如何，“其实”和“该有的”等未修改语义块均保持在原 cue 一侧；拼接全文与新文案逐字一致，cue 时间和 source anchors 不变。
- [x] AC2：前端 source 边界分别落入“其实”和“该有的”内部时，reconciliation 不再输出 `前文其 / 实该 / 有的后文结束`，而是选择原语义边界或合法降级边界。
- [x] AC3：执行“修改文案 -> 点击文案拆分 -> 删除拆出文案”后，艺术字拼接文本与当前保留文案逐字一致，无缺字、重字、乱序；“其实”“该有的”等受保护短语不跨 cue。
- [x] AC4：删除完整 cue 时对应 cue 进入 suppressed；撤销/恢复后原 cue 顺序、语义分区、ID 和样式恢复。本地临时投影与服务端回显不能改变已稳定的分区。
- [x] AC5：source timing 可用和容量/无 source 降级两条路径均有回归测试，断言字符守恒、合法边界、有限正时长和单调 `characterTimings`。
- [x] AC6：修改完全位于一个 cue 内时，只更新该 cue；跨 cue 编辑只允许差分影响区重新归属，未修改的左右语义块不跨边界。
- [x] AC7：初始全文艺术字 API/AI 分段缓存不重新请求、不改变；文字保存与 cut reconciliation 不增加外部模型调用。
- [x] AC8：现有文案编辑、拆分、删除、艺术字 API/轨道、ProjectStore、公共预览、compose、持久化和浏览器测试保持通过，`git diff --check` 与 Trellis validation 通过。

## Out Of Scope

- 调整 ASR、VAD、PCM、forced alignment、静音检测或音视频导出裁剪边界。
- 修改艺术字视觉样式、动画、字体宽度上限或时间轴交互设计。
- 为个别中文词语维护硬编码例外表。
- 每次文案操作重新调用 AI 生成全文艺术字分段。

## Technical Notes

- 权威数据分层：当前 transcript 决定“有哪些字符”；既有 cue 文本顺序决定“原语义分区”；source/edited timing 决定“何时显示”。三者不得互相替代。
- 修复需同时覆盖 `server/app.py:update_transcript_track_text_for_segment()` 和 `web/editor-art-model.js:partitionTranscriptTrack()`，只改其中一层会在另一条操作链路复发。
- `_cutReconciliation.overlay.text` 必须与可见 cue 的语义版本同步，供后续删除、撤销和服务端回显继续投影。
