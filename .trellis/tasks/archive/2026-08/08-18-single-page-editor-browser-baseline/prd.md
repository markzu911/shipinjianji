# 单页编辑器浏览器行为基线

## Goal

在开始统一文字剪辑、艺术字和画中画运行时之前，为当前编辑工作台建立可重复、无外部服务依赖的真实 Chromium 工作流基线。测试必须能捕获刷新、跨工具切换、预览/生成载荷和服务重启相关的状态回归，并为后续单页迁移提供可逐项转绿的验收入口。

## Background

- 父任务：`.trellis/tasks/08-13-project-optimization-audit`，本任务只交付其 Phase 0，不启动 B0 及后续单页实现。
- 当前前端测试主要是静态资源契约和 Node 行为脚本，没有 Playwright、Selenium 或其他真实浏览器工作流。
- `tests/app/conftest.py` 已提供临时 `DATA_DIR`、全局 job 清理和真实一秒 FFmpeg 视频；该隔离范围必须继续限定在 `tests/app/`。
- 开发服务固定使用 8001，但自动化测试不能依赖已启动的开发服务、固定端口、用户 `.env`、真实 `data/jobs` 或 `data/history`。
- 当前服务重启不会恢复内存 job；该已知缺口应被标记为待 Phase A 转绿的预期失败，而不是被断言为正确行为。

## Requirements

- R1：使用 Python Playwright 驱动真实 Chromium；测试依赖和浏览器安装命令必须可发现、可重复，不引入 npm 或前端构建系统。
- R2：浏览器测试通过临时端口启动当前 FastAPI 应用，并复用 `tests/app/` 的临时目录与全局状态隔离；不得连接正在运行的 8001 开发环境。
- R3：提供确定性短视频和转写/job fixture，直接建立测试所需服务端状态，不调用 ASR、文本模型、图像模型、视频模型或任何外部 HTTP 服务。
- R4：每个测试使用独立 browser context，收集未处理的 page error、严重 console error 和失败请求；测试结束必须关闭页面、浏览器、服务线程和临时媒体。
- R5：建立刷新恢复基线：编辑文字或删除范围并等待草稿保存后刷新，文案、删除范围和时间数据保持一致。
- R6：建立跨工具基线：创建或加载艺术字与画中画状态，切换三个工具后图层、选中项、公共预览和播放位置不被意外重置。
- R7：建立统一生成基线：从浏览器触发生成，捕获并校验 compose 请求包含当前文字剪辑、艺术字和画中画状态；Phase 0 不要求执行耗时渲染。
- R8：建立重启恢复的预期失败用例，明确当前缺失行为和 Phase A 的转绿条件；不得以断言当前数据丢失的方式固化缺陷。
- R9：浏览器行为断言优先使用可见 UI、URL、媒体状态和网络请求，不使用源码字符串替代工作流结果。

## Acceptance Criteria

- [x] 全新环境按文档安装依赖和 Chromium 后，可用一条 pytest 命令运行浏览器测试。
- [x] 测试使用随机本地端口和临时数据目录，不读取或修改真实用户 job/history，也不依赖开发服务是否运行。
- [x] 测试期间没有真实外部 AI/HTTP 请求；一旦发生即明确失败。
- [x] 编辑草稿刷新后，文字、删除范围和时间映射保持一致。
- [x] 文字、艺术字和画中画之间切换后，已有图层、公共预览和播放位置保持一致。
- [x] 浏览器触发的 compose 请求与当前三个工具状态一致，并可在不执行 FFmpeg 合成的情况下断言载荷。
- [x] 服务重启恢复用例以带原因的预期失败形式存在，并指向 Phase A，不降低其他测试的通过标准。
- [x] 聚焦浏览器测试、现有完整 pytest、全部 `web/*.js` 语法检查和 `git diff --check` 通过。

## Out of Scope

- 不修改文字剪辑、艺术字、画中画、播放、时间轴或生成的业务行为。
- 不实现 `EditorProjectStore`、统一视频/时间轴、iframe 迁移或旧 URL 重定向。
- 不修复服务重启恢复；只建立下一阶段可转绿的行为入口。
- 不保存用户媒体、浏览器 profile、截图、trace、视频或凭证到 Git。
