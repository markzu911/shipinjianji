# 修复重新开始等待草稿保存

## Goal

让尚未开始生成视频的用户可以明确放弃当前剪辑草稿并立即重新开始，避免草稿保存或 VAD 处理让按钮表现为无响应。

## Background

- 当前 `confirmAndResetProject()` 在用户确认后会等待正在进行或最近一次的草稿保存 Promise，再删除服务端草稿并重置页面。
- 草稿保存可能触发 VAD 首次加载或其他耗时处理；等待期间页面没有进行中反馈，用户会认为“重新开始”无效。
- 用户已经确认：未选择生成时，点击“重新开始”代表主动放弃当前草稿，不需要先保存。

## Requirements

- 用户确认“重新开始”后，不得发起新的草稿保存，也不得等待正在进行或排队的草稿保存。
- 重置必须使旧草稿保存失效，避免迟到响应重新写回本地状态或触发后续保存。
- 服务端草稿仍需清除，防止刷新或再次进入同一任务时恢复已放弃的选择。
- 清理服务端草稿失败时维持现有错误反馈，不静默伪装为成功。
- 已生成视频和剪辑历史不删除；生成视频流程不在本次修改范围内。

## Acceptance Criteria

- [x] 即使存在未完成的草稿保存 Promise，确认“重新开始”也不会等待该 Promise。
- [x] 确认后会取消/失效当前草稿保存运行时，并向当前任务发送草稿删除请求。
- [x] 草稿删除成功后直接进入上传初始页，本地草稿与撤销历史被清除。
- [x] 草稿删除失败时留在当前工程并显示错误，用户可以重试。
- [x] 真实浏览器验证“载入工程 -> 重新开始 -> 确认”可正常回到上传页，且没有页面错误。

## Out Of Scope

- 改变“生成视频”前必须完成权威草稿同步的现有规则。
- 删除历史版本、已生成成片或原视频文件。
- 重构通用确认弹窗或整个草稿保存状态机。
