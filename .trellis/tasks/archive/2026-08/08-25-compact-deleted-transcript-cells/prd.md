# 移除时间轴恢复按钮并压缩文案列表

## Goal

移除公共帧时间轴中已删除片段的红色恢复按钮，并将文字剪辑列表中的每一整行（选择圆点、时间、文案和播放按钮）按 50% 比例压缩，让同一高度内展示更多文案。

## Background

- 截图左下角红色按钮由 `web/app.js` 在 `.cut-timeline-deleted-marker` 中动态创建，用于选择并恢复已删除的分割视频片段；它不是文案单元格内部的恢复图标。
- 文字列表行 `.segment-item` 同时包含 `.segment-toggle`、`.segment-time-column`、`.segment-text` 和 `.segment-play-button`，桌面基础高度为 64px，圆点/播放按钮点击尺寸为 44px。
- 用户已明确：所有正常、已删除和空白文案行都要整体缩小，选择圆点与播放按钮也包含在 50% 缩放范围内；顶部统计卡片、标题和视频时间轴不缩放。

## Requirements

- R1：不再渲染公共帧时间轴中的 `.cut-timeline-deleted-marker` 红色恢复按钮，也不保留不可见的占位或焦点目标。
- R2：删除分割片段后仍保留既有全局撤销/重做历史和键盘快捷键；本任务只移除时间轴内的直接恢复入口。
- R3：将全部 `.segment-item` 行的高度、内边距、列宽、间距、文字字号/行高、选择圆点、时间标记和播放按钮按 50% 比例压缩；边框维持至少 1 个设备像素，列表仍占满容器宽度。
- R4：不改变删除范围、剪辑草稿、撤销历史、播放定位或生成结果。
- R5：长文案仍可换行，不得产生横向溢出；桌面和 375px 窄屏布局都要验证。
- R6：同步前端静态资源缓存版本，并更新静态/浏览器回归。
- R7：顶层画中画设置面板内的全部 UI（标题、文案选项、圆点、素材/生成方式、表单、按钮和生成结果）按当前实际渲染尺寸缩小 50%，面板仍铺满可用宽度且保留纵向滚动。
- R8：画中画文案列表在缩放后仍要把新选择项完整滚动到可见区域，不能因视觉坐标与逻辑滚动坐标比例不同而只滚动一半。
- R9：公共剪辑时间轴中已生成的帧缩略图必须纵向铺满缩略图轨道；剪后时间映射使用绝对定位时，不能因缺失纵向几何而形成 0px 高度。

## Acceptance Criteria

- [x] AC1：删除分割视频片段后，时间轴内不再出现红色逆时针箭头按钮或其空白占位。
- [x] AC2：Ctrl/Cmd+Z、Ctrl/Cmd+Y 与既有历史状态仍能撤销/重做片段删除。
- [x] AC3：正常文字、删除文字和空白片段的整行视觉高度与内部尺寸相对当前值压缩 50%，包含圆点、时间、文案和播放按钮。
- [x] AC4：长中文在桌面和 375px 窄屏均可换行且不横向溢出，顶部统计卡片和面板标题尺寸不变。
- [x] AC5：点击圆点仍切换删除，点击文案仍调整分段，播放按钮仍从对应原片时间播放，剪辑草稿保存不回退。
- [x] AC6：画中画设置内全部内容按 50% 显示，桌面与 375px 窄屏均铺满面板、无横向溢出，选段、生成及自动滚动行为不回退。
- [x] AC7：公共剪辑时间轴的可见缩略帧均包含背景帧且实际高度等于缩略图轨道高度，删除映射、分割和横向滚动不回退。

## Out of Scope

- 不移除或重写全局撤销/重做历史。
- 不修改后端剪辑边界或音频处理。
- 不重新设计整套文字剪辑列表。

## Risks

- 50% 缩放会把原 44px 圆点/播放控件降到约 22px，降低触控与可访问性；这是用户明确要求的视觉密度取舍，回归仍需保证键盘可聚焦和点击逻辑正确。
