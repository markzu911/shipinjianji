# 修复极短时间轴选区无法删除

## Goal

允许用户删除时间轴上短于当前 `0.1s` 门槛的有效小区间，同时保持播放头分割的最小片段保护和现有二次确认、微调、撤销、语音安全边界流程稳定。

## Background

- 当前 `web/app.js` 用同一个 `CUT_TIMELINE_MIN_RANGE = 0.1` 同时约束手动拖选删除、键盘边界微调、Timeline clip `minDuration`、播放头分割和 split point 恢复。
- `beginCutTimelineSelection()` 在松开时直接丢弃小于 `0.1s` 的选区并显示“未删除：区间过短或无效”，因此截图中的窄范围无法进入待确认状态。
- 后端没有同等的 `0.1s` 手动删除下限；现有 `tests/app/test_cut_draft.py` 已覆盖并接受 `2.05s..2.10s` 的 `0.05s` timeline range。
- 现有播放头分割单独需要 `0.1s` 最小片段保护，不能为了短删除同步放宽。

## Requirements

- R1：把“手动时间轴删除最小范围”与“播放头分割最小片段”拆成不同常量和校验路径。
- R2：短删除范围只要达到单帧粒度 `1/30s`，就必须保留为待确认选区，并继续支持二次点击/Enter 确认、取消、边界微调和撤销/重做。
- R3：鼠标创建、Timeline clip `minDuration`、键盘左右边界调整必须使用同一个短删除门槛，避免创建后又被微调逻辑扩回 `0.1s`。
- R4：播放头分割、split point 规范化和 `split_exact` 完整片段删除继续使用既有 `0.1s` 最小片段保护。
- R5：后端语音安全对齐、VAD/声学边界、草稿 schema、生成和预览流程不改变；物理边界仍可在保存时安全吸附。
- R6：极窄选区仍需有稳定的视觉命中区和无障碍入口，左右手柄、主体和取消按钮不能让确认入口不可点击。
- R7：补充真实 Chromium 回归，覆盖短选区创建、二次确认、保存/预览、撤销/重做以及桌面和 375px；同时证明分割门槛未被放宽。

## Acceptance Criteria

- [x] AC1：`1/30s <= duration < 0.1s` 的拖选在 pointerup 后保留，不显示“区间过短”，并进入现有待确认状态；短于一帧的范围继续安全拒绝。
- [x] AC2：该短选区可通过主体点击或 Enter 打开确认框，确认后进入已提交删除状态并写入 cut draft。
- [x] AC3：短选区可拖动主体/边界、使用键盘微调、取消、撤销和重做，且不会被自动扩成 `0.1s`。
- [x] AC4：短选区保存后预览/生成消费同一语义范围；语音安全物理吸附与保留文字保护保持既有行为。
- [x] AC5：播放头仍不能创建短于 `0.1s` 的分割片段，历史 split point 规范化规则不变。
- [x] AC6：选区主体、两侧手柄和取消按钮在桌面/375px 下均可操作，确认点击不会被重叠手柄吞掉。
- [x] AC7：相关前端契约、真实浏览器工作流、剪辑草稿/渲染测试、JS 语法和 `git diff --check` 通过。

## Out of Scope

- 不改变播放头分割或 `split_exact` 删除的 `0.1s` 最小片段规则。
- 不新增时间输入框、帧吸附开关或新的删除手势。
- 不改变 VAD、声学吸附和媒体渲染算法。
- 不处理暂停中的“段落试听结束后播放头无法移动”任务。

## Key Decisions

- 手动删除最低粒度固定为单帧 `1/30s`，与现有时间轴 step 一致；不接受任意大于零的亚帧范围。
- 播放头分割和 split point 的 `0.1s` 最小片段规则保持独立且不变。
- 本任务按轻量前端交互修复处理，保持 PRD-only，不增加后端接口、schema 或新状态模型。
