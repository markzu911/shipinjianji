# 排查时间轴文案与实际文案不一致

## Goal

定位文字剪辑列表与公共时间轴显示文案不一致的根因，明确错误数据首次出现在哪个转换层，并给出可复验的证据和修复范围。本轮仅诊断，不修改产品代码或用户工程数据。

## Background

- 用户截图中的文字列表在剪后约 `00:19` 显示保留文案“ 一起给你画的那条正常的线。”，同时保留前一句“而是你身边所有人”。
- 同一画面的公共时间轴在约 `00:19-00:22` 显示的片段文案与列表/实际口播不一致；约 `00:22` 还涉及被删重复句、保留重复句和自动空白范围。
- 页面运行于当前本地开发服务，仓库中另有尚未提交的 UI 密度/时间轴修改，诊断必须区分当前代码行为、未提交改动和旧 job 持久化数据。

## Requirements

- R1：识别截图对应 job、cut draft revision、时间轴数据源和文字列表数据源。
- R2：沿 `project-state/cutDraft -> retained transcript -> EditorProjectStore -> TimelineController` 追踪文本、源时间和剪后时间，找出首次不一致的位置。
- R3：区分文本内容错误、时间映射错误、片段聚合错误、旧缓存/旧草稿未刷新和纯视觉截断。
- R4：检查刚完成的首字声学边界修复是否只改变物理 `start`，以及它是否意外影响剪后 transcript 或公共时间轴的文字投影。
- R5：保持 `data/jobs`、`data/history`、用户附件和当前未提交 UI 工作只读，不通过刷新/保存覆盖现场。

## Acceptance Criteria

- [x] AC1：用 job 数据和浏览器/代码证据逐字列出文字列表、权威剪后 transcript、Store frame 和时间轴条目的对应关系。
- [x] AC2：给出一个明确的首个错误层与因果链，包含相关文件、函数和字段。
- [x] AC3：说明问题是否由本轮声学边界修复引入，并用提交前后契约或持久化字段证明。
- [x] AC4：提出最小修复范围、需要新增的回归测试和不应触碰的行为，但不在本轮实施。

## Out Of Scope

- 不修改时间轴 UI、文案聚合、草稿、工程快照或媒体文件。
- 不重新生成成片，不重新请求 AI/ASR，不提交当前工作区改动。
