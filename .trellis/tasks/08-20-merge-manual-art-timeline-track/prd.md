# 合并手动艺术字时间轴轨道

## Goal

将同一视频中所有普通非文案艺术字（包括手动新增和 AI 推荐确认后的 overlay）收拢到一条独立的手动艺术字轨道，不再每新增一个艺术字就创建一条轨道；手动艺术字轨道必须与视频文案艺术字轨道明确分开。

## Background

- `web/editor-art-model.js:768` 的 `buildTimelineTracks()` 已将同一 `trackId` 的文案艺术字 cue 合并为 `art:transcript:<trackId>` 轨道，但所有非文案艺术字仍以 `art:overlay:<overlayId>` 生成独立轨道。
- `web/editor-art-tool.js:584` 每次手动新增都创建独立 overlay；overlay 的文案、样式、时间和位置是可单独编辑的业务对象，合并轨道不能合并这些对象。
- 文案艺术字以 `trackType === "transcript" && trackId` 识别，共享整轨样式并按 cue 分段播放；手动艺术字不得加入该轨道或触发文案整轨批量更新。
- 现有校验允许多个手动艺术字的时间区间重叠，合并后仍必须能同时预览、合成和单独选择。
- 用户已确认手动艺术字轨道必须与文案艺术字轨道分开；按推荐方案，AI 推荐确认后的普通非 `transcript` 艺术字也进入手动艺术字轨道，不增加第三种轨道身份。

## Requirements

- R1：所有非 `transcript` 的普通艺术字（包括手动新增和 AI 推荐确认后的 overlay）在公共时间轴中共用一条稳定身份的手动艺术字轨道，每个 overlay 仍是该轨道中的独立 clip。
- R2：手动艺术字轨道与 `art:transcript:<trackId>` 文案艺术字轨道必须拥有不同身份和展示语义，不得因为都属于 `kind === "art"` 而混成一条轨道。
- R3：合并轨道不得改变手动 overlay 的 `id`、文案、样式、位置、起止时间、源时间锚点、预览层级或 compose payload。
- R4：轨道内任一手动 clip 仍可单独选择、拖动起止时间、修改文案与样式、删除、撤销和重做；这些操作不得批量改动其他手动 clip。
- R5：手动艺术字时间重叠时，公共时间轴仍必须让每个 clip 可见且可选，不得因为同轨道绘制而完全遮挡。
- R6：新建、删除、刷新草稿恢复、文字剪辑时间重对齐与历史兼容数据都必须由同一轨道派生函数得到一致结果，不在 Store 中增加第二份轨道权威状态。
- R7：点击任一公共效果片段主体时，播放指示条必须定位到鼠标对应的剪后时间；横向滚动不得产生偏移，选择被拒绝或几何无效时不得产生错误或重复 seek，拖动和缩放语义保持不变。

## Acceptance Criteria

- [x] AC1（R1、R2）：给定至少两个手动艺术字、一个 AI 确认的普通艺术字和一条多 cue 文案艺术字，派生时间轴只有一条手动艺术字轨道和一条文案艺术字轨道，两者 ID 和名称不同。
- [x] AC2（R3）：合并前后 overlay 数量、顺序、ID、内容、样式、位置、编辑/源时间和 compose/preview 顺序保持不变。
- [x] AC3（R4）：从公共时间轴选择或拖动任一手动 clip 只更新对应 overlay，selection 指向正确 `art:<overlayId>`，撤销/重做只影响该次修改。
- [x] AC4（R5）：至少两个时间重叠的手动艺术字在同一逻辑轨道下仍各有可见、可聚焦、可选择的时间轴 clip，预览与合成同时保留两者。
- [x] AC5（R6）：连续新增、删除中间项、草稿恢复和文字剪辑重对齐后，手动轨道仍只有一条，clip 不丢失且文案轨道不受影响。
- [x] AC6（R7）：手动艺术字、文案艺术字和画中画片段主体点击均只 seek 一次并与实际点击位置对齐；横向滚动后仍对齐，无效几何回退片段起点，程序化选择继续 seek 起点。

## Out Of Scope

- 不把手动艺术字合并进文案艺术字轨道。
- 不把多个手动 overlay 压成一个 overlay，不统一改写它们的文案、样式或时间。
- 不修改艺术字渲染、AI 推荐算法、全文分段或服务端 compose 契约。
- 不增加前端框架、第二个 Store 或私有时间轴。
