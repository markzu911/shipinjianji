# 文案播放按钮仅播放当前段落

## Goal

让用户点击文字剪辑区某条文案后的播放按钮时，只试听当前展示段落，避免播放自动延续到后续文案，便于逐段核对转写和剪辑结果。

## Background

- 每条文字展示行已经有独立播放按钮，并通过 `data-display-start/end` 记录该行对应的原视频时间范围。证据：`web/app.js:593-671`。
- 点击按钮后，`previewTextSegment` 已经从当前行起点开始播放，并设置 `transcriptPreviewRange`。证据：`web/app.js:2740-2758`。
- 当前 `timeupdate` 处理在播放位置到达行末时只清除 `transcriptPreviewRange`，没有暂停视频，因此会继续播放后续段落。证据：`web/app.js:3477-3515`。
- 普通预览、已删除文字试听、空白试听和裁剪衔接预览共用同一个视频元素；本改动必须只约束文案行播放按钮启动的临时试听。

## Requirements

- R1：点击任一有效文案展示行末尾的播放按钮后，从该行的 `data-display-start` 开始播放。
- R2：播放到该行的 `data-display-end` 时自动暂停，不继续播放下一条文案；播放头停留在当前段落末尾附近，不自动跳回段首。
- R3：普通文案、因删除区间拆出的展示片段和已删除文字行使用相同的单段播放行为；已删除文字在该行范围内继续临时绕过“跳过已删除区间”逻辑。
- R4：单段播放结束后清除临时试听范围，使用户随后使用公共播放按钮、进度条或时间轴 seek 时恢复现有的完整剪辑预览和自动跳过删除区间行为。
- R5：用户在单段播放过程中执行公共 seek、点击另一条文案播放按钮或重置项目时，沿用现有状态清理规则，不让旧段落的结束边界误停新的播放。
- R6：播放按钮的 `title` 和 `aria-label` 明确表达“播放当前段落”，保留现有播放图标、至少 44px 点击区和事件委托优先返回行为。
- R7：单段结束时通过现有状态区域给出简短完成反馈；不打开文字编辑弹窗，不改变删除选择、剪辑草稿或撤销历史。
- R8：补充前端契约测试并进行浏览器行为验证，覆盖普通文字和已删除文字的起点、终点、暂停及后续公共播放恢复。
- R9：播放或主动跟随定位时，当前“播放中”文案行应对齐到吸顶删除统计栏下方的固定顶部锚点，后续文案通过列表向上滚动进入该位置；不得继续使用仅保证可见的最近边缘滚动。
- R10：自动跟随的目标滚动量必须限制在面板的 `maxScrollTop` 内；列表尚可继续向上滚动时当前行保持顶部对齐，到达文案尾部、面板无法继续上滚后，当前绿色行才随最后几条文案自然向下移动。
- R11：自动跟随继续尊重 `prefers-reduced-motion`，不改变手动滚动、删除选择、播放区间或移动端布局；重复命中同一展示行时不重复启动滚动动画。

## Acceptance Criteria

- [x] AC1（R1、R2）：点击普通文案行播放按钮后，视频从该行起点开始，并在该行末尾自动暂停；不会进入下一条文案。
- [x] AC2（R3）：点击已删除文字行播放按钮后，该文字可完整试听，并在该展示行末尾自动暂停，不播放后续内容。
- [x] AC3（R4、R5）：单段试听结束或用户主动 seek 后，公共播放按钮可按现有剪辑预览规则继续播放，删除区间仍会被自动跳过，且不会被旧终点再次暂停。
- [x] AC4（R6、R7）：按钮的鼠标提示和无障碍名称都说明“播放当前段落”；点击和播放结束均不打开分段编辑，不修改删除状态、草稿或撤销历史。
- [x] AC5（R8）：相关自动化测试通过；桌面浏览器中验证普通/已删除文案的单段播放，控制台无新增错误。
- [x] AC6（R9、R10）：播放中行在列表仍可滚动时固定对齐统计栏下方；接近最后一屏时滚动位置停在最大值，绿色行才向下移动，不被统计栏遮挡。
- [x] AC7（R11）：相同行重复更新时间不产生额外滚动；减少动态效果设置使用即时滚动，桌面与 375px 均无横向溢出或控件重叠。

## Out of Scope

- 不改变预览区公共播放/暂停按钮的整段播放语义。
- 不改变空白试听、裁剪衔接预览、时间轴 seek 或当前行高亮判定；自动跟随仅调整滚动锚点、尾部 clamp 和动画策略。
- 不新增循环播放、播放速度、连续逐段播放或新的持久化字段。
- 不修改后端媒体接口、转写分段算法、删除区间算法或页面布局。

## Key Decisions

- “仅播放当前段落”定义为到达当前展示行末尾后暂停，并保留播放头在段末；再次点击该行按钮仍从段首重新试听。
- 使用现有 `transcriptPreviewRange` 作为临时边界，不新增第二套播放器或持久状态。
- 自动跟随使用滚动面板内的确定性顶部目标：`当前 scrollTop + 行 top - 顶部锚点`，再 clamp 到 `0..maxScrollTop`；这既保持中段固定，又让尾部自然下移。
- 本任务是轻量前端行为修复，只需要 `prd.md`；无需新增 `design.md` 或 `implement.md`。

## Risks And Deferred Items

- `timeupdate` 事件存在浏览器调度粒度，实际暂停点允许在行末附近产生极小误差，但不得可感知地播放下一段语音。
- 吸顶统计栏高度会随响应式文案换行变化，顶部锚点必须读取实际高度，不能写死桌面像素值。
- 自动化以现有前端契约测试为基础，真实媒体终点行为在浏览器中补充验证；引入新的前端测试框架不属于本任务。
