# 文案单段播放与平滑跟随滚动

## Goal

让用户逐段试听文字剪辑结果时，播放严格停在当前展示段落末尾，并让“播放中”绿色框稳定停在顶部锚点、文案连续向上滚动；动画修复必须运行在拆分后的独立前端模块中。

## Background

- 每条文字展示行已有独立播放按钮，并通过 `data-display-start/end` 记录对应的原视频时间范围；`previewTextSegment` 与 `timeupdate` 已实现从行首播放、在行末暂停和恢复公共播放语义。证据：`web/app.js:2898-2915`、`web/app.js:3615-3651`。
- 普通预览、已删除文字试听、空白试听和裁剪衔接预览共用同一个视频元素；现有单段播放行为已经通过前端契约测试，动画拆分不得改变该行为。
- 当前跟随滚动实现仍位于约 175 KB 的 `web/app.js`，通过原生 `scrollTo({ behavior: "smooth" })` 独立启动滚动；活动行样式先切换、滚动随后发生，导致绿色框先跳到下一行再向上移动。证据：`web/app.js:1780-1810`。
- 前端没有构建器或 ES module，现有拆分方式是在 `app.js` 前通过有版本号的 `defer` 脚本加载独立全局模块；本次必须沿用该方式，使动画修复落在拆分后的功能模块中。

## Requirements

- R1：点击任一有效文案展示行末尾的播放按钮后，从该行的 `data-display-start` 开始播放。
- R2：播放到该行的 `data-display-end` 时自动暂停，不继续播放下一条文案；播放头停留在当前段落末尾附近，不自动跳回段首。
- R3：普通文案、因删除区间拆出的展示片段和已删除文字行使用相同的单段播放行为；已删除文字在该行范围内继续临时绕过“跳过已删除区间”逻辑。
- R4：单段播放结束后清除临时试听范围，使用户随后使用公共播放按钮、进度条或时间轴 seek 时恢复现有的完整剪辑预览和自动跳过删除区间行为。
- R5：用户在单段播放过程中执行公共 seek、点击另一条文案播放按钮或重置项目时，沿用现有状态清理规则，不让旧段落的结束边界误停新的播放。
- R6：播放按钮的 `title` 和 `aria-label` 明确表达“播放当前段落”，保留现有播放图标、至少 44px 点击区和事件委托优先返回行为。
- R7：单段结束时通过现有状态区域给出简短完成反馈；不打开文字编辑弹窗，不改变删除选择、剪辑草稿或撤销历史。
- R8：补充前端契约测试并进行浏览器行为验证，覆盖普通文字和已删除文字的起点、终点、暂停及后续公共播放恢复。
- R9：播放或主动跟随定位时，当前“播放中”文案行应对齐到吸顶删除统计栏下方的固定顶部锚点，后续文案通过列表向上滚动进入该位置；不得继续使用仅保证可见的最近边缘滚动。
- R10：自动跟随的目标滚动量必须限制在面板的 `maxScrollTop` 内；列表尚可继续向上滚动时当前行保持顶部对齐，到达文案尾部、面板无法继续上滚后，当前绿色行才随最后几条文案自然向下移动。
- R11：自动跟随继续尊重 `prefers-reduced-motion`，不改变手动滚动、删除选择、播放区间或移动端布局；重复命中同一展示行时不重复启动滚动动画。
- R12：先把目标计算、去重、动画帧、取消和清理状态从 `web/app.js` 抽到独立的 `web/transcript-follow-scroll.js`；新模块暴露单一 `window.TranscriptFollowScroll` 全局，`app.js` 只负责切换活动行并调用控制器，不再定义跟随滚动实现或持有其帧状态。
- R13：非减少动态效果模式使用同一个可取消的 `requestAnimationFrame` 动画同步推进面板 `scrollTop` 和活动行临时 `transform`。列表中段时绿色框在工具栏下方锚点保持不动、文案从其后向上滚动；到达 `maxScrollTop` 后，绿色框才按剩余距离平滑向下移动到自然位置。
- R14：切换目标、重新渲染列表、关闭跟随或检测到用户滚轮、触摸、指针及键盘滚动意图时，必须取消旧动画、移除临时 transform/样式和监听器；旧帧不得继续写入新 DOM。减少动态效果模式直接定位且不添加临时动画样式。
- R15：`index.html` 必须在 `app.js` 前加载带版本号的新脚本，服务端无缓存清单和静态资源测试同步更新；Node 行为测试直接加载独立模块，覆盖中段固定、尾部下移、重定向取消、用户取消、去重和 reduced-motion。

## Acceptance Criteria

- [x] AC1（R1、R2）：点击普通文案行播放按钮后，视频从该行起点开始，并在该行末尾自动暂停；不会进入下一条文案。
- [x] AC2（R3）：点击已删除文字行播放按钮后，该文字可完整试听，并在该展示行末尾自动暂停，不播放后续内容。
- [x] AC3（R4、R5）：单段试听结束或用户主动 seek 后，公共播放按钮可按现有剪辑预览规则继续播放，删除区间仍会被自动跳过，且不会被旧终点再次暂停。
- [x] AC4（R6、R7）：按钮的鼠标提示和无障碍名称都说明“播放当前段落”；点击和播放结束均不打开分段编辑，不修改删除状态、草稿或撤销历史。
- [x] AC5（R8）：相关自动化测试通过；桌面浏览器中验证普通/已删除文案的单段播放，控制台无新增错误。
- [x] AC6（R9、R10）：播放中行在列表仍可滚动时固定对齐统计栏下方；接近最后一屏时滚动位置停在最大值，绿色行才向下移动，不被统计栏遮挡。
- [x] AC7（R11）：相同行重复更新时间不产生额外滚动；减少动态效果设置使用即时滚动，桌面与 375px 均无横向溢出或控件重叠。
- [x] AC8（R12、R15）：跟随滚动实现和状态只存在于 `web/transcript-follow-scroll.js`，`app.js` 通过 `window.TranscriptFollowScroll.createController()` 集成；页面加载顺序、版本号、无缓存响应和全局命名空间均有契约测试。
- [x] AC9（R13）：正常动态效果下逐帧验证中段活动行的视觉 top 始终等于工具栏底部加 8px，同时面板内容持续向上；尾部逐帧验证 `scrollTop` 不超过最大值且活动行从锚点连续向下到自然位置，无先跳后滚。
- [x] AC10（R14）：动画中切换活动行、列表重渲染或触发手动滚动意图后，旧 RAF 不再改变 `scrollTop`，旧行不残留 transform、动画 class 或监听器；reduced-motion 只产生一次即时定位。
- [x] AC11（R12-R15）：聚焦 Node/前端契约测试和全量 pytest 通过；在开发服务桌面与 375px 浏览器中播放跨多行文案，确认动画连续、布局不溢出、控制台无新增错误，生产分支与生产服务不变。

## Out of Scope

- 不改变预览区公共播放/暂停按钮的整段播放语义。
- 不改变空白试听、裁剪衔接预览、时间轴 seek 或当前行高亮判定；自动跟随仅调整滚动锚点、尾部 clamp 和动画策略。
- 不新增循环播放、播放速度、连续逐段播放或新的持久化字段。
- 不修改后端媒体接口、转写分段算法、删除区间算法或页面布局。
- 不在本任务中拆分 `app.js` 的上传、草稿、时间轴、历史或媒体播放等其他功能；只建立文案跟随滚动这一条可独立验证的前端模块边界。

## Key Decisions

- “仅播放当前段落”定义为到达当前展示行末尾后暂停，并保留播放头在段末；再次点击该行按钮仍从段首重新试听。
- 使用现有 `transcriptPreviewRange` 作为临时边界，不新增第二套播放器或持久状态。
- 自动跟随使用滚动面板内的确定性顶部目标：`当前 scrollTop + 行 top - 顶部锚点`，再 clamp 到 `0..maxScrollTop`；这既保持中段固定，又让尾部自然下移。
- 先完成行为保持型模块拆分，再在新模块内替换原生 smooth scroll；不在 `app.js` 中临时修好后再搬运。
- 新模块采用与 `timeline-model.js` 一致的浏览器全局/CommonJS 双导出形式，不引入 bundler、框架或新的运行时依赖。
- 动画使用可取消的自有 RAF 时间线，不依赖不可观察、不可可靠重定向的原生 smooth scroll；活动行临时使用不透明提升层防止滚动文字透叠。

## Risks And Deferred Items

- `timeupdate` 事件存在浏览器调度粒度，实际暂停点允许在行末附近产生极小误差，但不得可感知地播放下一段语音。
- 吸顶统计栏高度会随响应式文案换行变化，顶部锚点必须读取实际高度，不能写死桌面像素值。
- 自动化以现有前端契约测试为基础，真实媒体终点行为在浏览器中补充验证；引入新的前端测试框架不属于本任务。
- transform 动画会暂时把活动行提升到滚动内容之上；若未在所有取消路径清理，可能残留错位或遮挡，因此控制器必须集中拥有并清理 RAF、样式和面板监听器。
