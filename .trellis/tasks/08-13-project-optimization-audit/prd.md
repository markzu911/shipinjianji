# 项目优化评估与路线规划

## Goal

基于当前代码、测试、运行界面和历史问题，对视频剪辑项目进行一次有证据的全局审计，识别最值得优化的产品与工程问题，并形成按用户收益、故障风险和实施成本排序的路线图。

## Background

- 当前产品已覆盖文字剪辑、艺术字、画中画、统一时间轴、抖音预览和最终视频生成等核心流程。
- 项目处于高频迭代阶段，当前工作区已有 32 处未提交改动；审计必须保留这些改动，不做清理或回退。
- 历史反馈反复涉及跨页面状态不同步、剪后时间戳与艺术字错位、预览与导出不一致、多个生成入口行为分叉等问题。
- 当前测试基线为 133 passed、1 warning；现状可运行，路线不以整体重写为目标。
- 后端任务状态主要存在进程内字典中，多个 API 明确在服务重启后返回“任务不存在或服务已重启”。
- 顶层编辑器已能统一生成，但艺术字和画中画子页面仍各自拥有图层状态，并通过跨 iframe 消息发送生成载荷和时间轴 HTML 快照。
- 本任务当前只做评估与规划，不直接修改业务代码。

## Requirements

- R1：梳理从上传、识别、文字剪辑、艺术字、画中画、预览到最终生成的完整数据流，并标记重复状态源和边界转换。
- R2：审查当前前端架构、后端职责、持久化机制、任务状态、媒体处理、错误处理和资源生命周期。
- R3：审查桌面与移动端的核心编辑工作流，包括信息密度、操作路径、反馈状态、无障碍和响应式稳定性。
- R4：结合现有测试和历史缺陷，识别高风险但缺少自动化覆盖的路径。
- R5：每个优化项必须包含问题证据、用户影响、推荐方案、风险、预计工作量和验收方式。
- R6：路线图按 P0/P1/P2 分级，并区分结构性修复、体验优化和可延后增强。
- R7：不把与当前目标无关的新功能、技术栈重写或纯视觉改版混入优先路线。
- R8：推荐路线必须优先降低用户成果丢失、预览与导出不一致、刷新后状态回退这三类风险。

## Acceptance Criteria

- [ ] 给出当前系统的关键数据流与状态所有权说明。
- [ ] 至少覆盖可靠性、编辑体验、性能、可维护性和测试五个维度。
- [ ] 所有 P0/P1 建议都能追溯到代码、测试、运行界面或历史问题证据。
- [ ] 给出可独立验收的分阶段实施顺序，说明依赖关系和回滚点。
- [ ] 明确本轮不实施业务改动，并在开始任何实施前再次由用户审批最终规划摘要。

## Out of Scope

- 本轮不直接实现优化项。
- 不清理、重置或提交当前工作区已有改动。
- 不以更换框架、重写整个前端或拆分微服务作为默认方案。
- 不新增尚未验证用户价值的编辑功能。

## Open Questions

- 是否采用推荐的“可靠性优先”顺序：先做项目状态持久化、前端单一状态源和端到端测试，再做文件拆分、性能与产品化 UI；待用户确认。
